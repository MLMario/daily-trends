## 1. Context

A trend-discovery pipeline that runs daily and surfaces AI-focused content the operator can turn into Substack / LinkedIn / Instagram posts. It pulls content from four eventual source families:

(a) **News** — Hacker News front page and TechCrunch's AI category, fetched live by a subagent.
(b) **Vendor blogs** — Anthropic (`claude.com/blog`) and OpenAI Developers (`developers.openai.com/blog`) plus any future first-party AI vendor blogs, fetched by a separate subagent.
(c) **Instagram Reels** — scraped from a curated creator list (Bright Data + yt-dlp) and transcribed locally via faster-whisper on GPU. *Scrape pathway and Whisper local-runtime both feasibility-confirmed 2026-05-28; build pending — see "Implementation Slices" below.*
(d) **X posts** — scraped from a curated creator list. *Deferred — see "Implementation Slices" below.*

All collected content is clustered into topics by an LLM subagent, which produces `trending_topics.json` plus per-topic content recommendations for the operator's publishing channels (configurable; currently Substack, LinkedIn, Instagram). The output is delivered to the operator (`mariogj1987@gmail.com`) via email and saved to disk under a versioned `runs/<run_id>/` directory.

## 1a. Implementation Slices

The full pipeline ships in three additive slices. Each slice is a working end-to-end pipeline; later slices add sources without restructuring shared modules.

**Slice A — News + Vendor Blogs (initial implementation, PRD: GitHub issue #1).**
- Sources: News subagent (HN + TC AI) and Vendor blogs subagent (Anthropic + OpenAI Devs).
- All downstream steps (normalize → cluster → recommendations → email) wired and tested.
- Two orchestration skills shipped: `run-trends` and `recluster`.

**Slice B — Instagram Reels. _Feasibility-confirmed (2026-05-28); build pending._**
- Bright Data Web Scraper Dataset API (dataset `gd_lyclm20il4r5helnj`, `type=discover_new&discover_by=url`, MM-DD-YYYY date range) for metadata + yt-dlp for `.mp4` download. yt-dlp resolves the canonical `instagram.com/p/<shortcode>/` URL without cookies; CDN `video_url` is retained in metadata as a fallback. The reels-only dataset rejects a `post_type` field — do not send it.
- faster-whisper (`small`, `compute_type="float16"` on GPU) transcription with auto-detect language + two-pass `task="translate"` for non-English Reels (pass 1 transcribes + detects language, pass 2 translates to English; pass 2 only fires when `info.language != "en"`). Feasibility-confirmed against the `@hellovidya` `.mp4` fixture: ~5.5 s warm-cache per ~3 min Reel, ~1.3 GB peak VRAM of 16 GB, on-disk model 464 MB. Output schema `{text, text_en?, language, duration_sec}` honored. Operational constraints `scripts/transcribe_reels.py` MUST honor: (i) `compute_type="float16"` is mandatory on this GPU — `int8`/`int8_float16` trip `cuBLAS CUBLAS_STATUS_NOT_SUPPORTED` on Blackwell sm_120; (ii) prepend wheel-installed `nvidia/{cublas,cudnn,cuda_nvrtc}/bin/` to `PATH` before importing `faster_whisper` on Windows (`os.add_dll_directory` alone is insufficient for CT2's transitive DLL loads); (iii) hard-fail when `device != cuda` rather than silently falling back to CPU (CPU is ~3× slower); (iv) per-Reel try/except → `ErrorLog` with `step="transcribe_reels"`, severity warning, skip on failure (no retry). See `docs/adr/0003-whisper-local-runtime.md` for the full feasibility record and the model-cache `download_root=` configuration.
- `creators/accounts.json[instagram]` populated. Seed creator: `hellovidya`. See `docs/adr/0002-instagram-scraper-provider.md` for the scrape-pathway investigation record and the B.1–B.5 build plan.

**Slice C — X posts. _Deferred indefinitely (2026-05-28)._**
- Investigation across Bright Data, Apify Free, and scrapegraphAI confirmed all three unauthenticated X providers fail on the target account class: small AI-researcher accounts are hidden by X's logged-out content gate, and large accounts are served stale snapshots. Re-opening this slice requires an authenticated session-pool provider — paid Apify with session pool, X official API Basic, or self-hosted Playwright with logged-in cookies. See `docs/adr/0001-x-scraper-provider.md` for the full investigation record and the prerequisites for re-opening.
- Original design surface (Bright Data X Posts Dataset, `creators/accounts.json[x]`, `x_lookback_days`) is preserved in this document for future revival but is not on the active build path.

Each slice extends the same `CorpusNormalizer` module additively (more readers, no other module changes) and the same `config.json` (more keys: `instagram_lookback_days`, `x_lookback_days`, etc.). Subagent prompts (clustering, recommendations) do not change between slices — they operate on the unified corpus schema.

## 2. Objective

Produce, per run, two JSON artifacts — `trending_topics.json` (topic groupings + summaries + other-notable items) and `content_recommendations.json` (per-channel ideas per topic) — and email the operator an HTML digest plus a structured error summary.

**Must-haves**

- **No silent failures.** Errors, warnings, and consequential-info events are logged in detail to `runs/<run_id>/errors.log`; the email's "Errors & Skips" section gives a structured Python-rendered summary so missing data is never invisible.
- **Config-driven.** `creators/accounts.json` (which accounts — populated in slices B/C) and `config.json` (lookback windows, email_mode, content channels, clustering threshold, vendor blog list) are editable without touching pipeline code.
- **Outputs are versioned, never overwritten.** Each run writes to a fresh `runs/<UTC-timestamp>/` directory. Cross-run duplication is acceptable.
- **Graceful slow-day behavior.** If normalized corpus < `min_corpus_for_clustering` (default 4), the pipeline skips clustering + recommendations and renders a "light signal" email branch. An email always lands, so inbox status reflects pipeline status.
- **Confidence-gated delivery.** `email_mode` config flag (`"draft" | "send"`) lets the operator preview rendered emails as Gmail drafts before flipping to direct send.

## 6. Harness and Model Decisions

**Capability → harness tool mapping**

| Capability | Harness tool |
|------------|--------------|
| Orchestrate sequence, manage run_id, route errors | Claude Code main session (via `/run-trends` skill) |
| Re-run synthesis steps against existing corpus | Claude Code main session (via `/recluster` skill) |
| Find + summarize trending news | Fresh-context subagent via Agent tool (WebFetch) |
| Find + summarize vendor blog posts | Fresh-context subagent via Agent tool (WebFetch) |
| Deterministic data transforms (normalize, render, dispatch) | Python deep modules invoked via Bash entry-point scripts |
| LLM synthesis (clustering, recommendations) | Fresh-context subagents via Agent tool (general-purpose) |
| Send HTML email with attachments | Python (GmailSender), google-api-python-client (Gmail API, scope `gmail.send`) |
| (Slice B) Scrape IG metadata + filter videos | Python + Bright Data Web Scraper API |
| (Slice B) Download Reel `.mp4` binary | yt-dlp invoked from Python |
| (Slice B) Local speech-to-text + translation | `faster-whisper` (small, float16 on GPU; int8 CPU fallback) in Python — see ADR-0003 |
| (Slice C) Scrape X posts per account per date range | Python + Bright Data X Posts Dataset API |

**Harness:** Claude Code main session as orchestrator. Skill-based entry (`.claude/skills/run-trends/SKILL.md` and `.claude/skills/recluster/SKILL.md`). Reasoning: the workflow blends deterministic Python with LLM judgment stages and benefits from Claude Code's ability to drive both via Bash and Agent tools without leaving the local environment. State lives on local disk; secrets stay in `.env` and `credentials/` outside any cloud harness. Migration to a headless Python orchestrator using the Anthropic SDK is anticipated for scheduled production runs (Open Question — Cadence), but the skill body is designed to translate mechanically.

**Concurrency:** Source-fetch subagents (news + vendor_blogs in slice A; potentially news + vendor_blogs + IG-metadata-fetch in later slices) are spawned in a single tool block to execute concurrently. Clustering and recommendations remain sequential (strict dependency).

**Prompt-config wiring:** Prompt files in `prompts/` are static text. The orchestrator reads each prompt at invocation time, appends relevant config values as prose, and passes the combined string to the Agent tool. No templating engine.

**Model:** **Sonnet 4.6** for all subagents (news, vendor_blogs, clustering, recommendations). The rule of thumb is the least intelligence that does the job reliably — these are retrieval + light summarization + bounded ideation, not requiring Opus-level reasoning. Easy upgrade path: change the `model` parameter on a single Agent call to `opus` later if topic quality is weak. The orchestrator itself runs as Opus 4.7 because it handles error routing across all stages.

## 6a. Module Breakdown

Deep modules (encapsulate logic behind a simple interface that rarely changes; testable in isolation):

- **RunWorkspace** — owns run lifecycle. `new_run()` generates a UTC-minute-precision run_id and creates the directory tree. `existing_run(run_id)` resolves paths against an existing run for `/recluster`. Exposes typed paths for every file the pipeline reads or writes.
- **ErrorLog** — append-only JSON-lines writer plus a reader producing a grouped `ErrorSummary`. Supports `severity ∈ {error, warning, info}` and optional `kind: "consequential"` for info entries that affect downstream output (promoted into the email summary).
- **CorpusNormalizer** — single deterministic transform that reads all per-source JSON inputs, unions into the corpus schema, applies `word_count < 30` filter, logs the dropped count. Adding IG transcripts or X posts in later slices is a new reader inside this module — no other module changes.
- **EmailRenderer** — reads `trending_topics.json` + `content_recommendations.json` + error summary, joins topics and recommendations by `topic_id`, substitutes into the HTML template. Two render paths: full (topic cards + Other Notable + Errors) and light-signal (Other Notable + Errors + corpus-size note). Selected by reading whether `skipped_clustering.json` is present in the workspace.
- **GmailSender** — wraps `google-api-python-client`. Encapsulates OAuth load + token refresh, multipart/mixed MIME assembly (HTML body + JSON attachments), and dispatch by mode (`drafts.create` for `email_mode: "draft"`; `messages.send` for `"send"`). Returns a `SendResult`.

Thin composition layer (entry-point scripts and skill bodies): `init_run.py`, `normalize_corpus.py`, `send_email.py`, plus the two skill markdown files. No logic worth testing in isolation; exercised by end-to-end dry runs.

**Tests** (pytest):
- `CorpusNormalizer`: fixture-driven; schema correctness, drop filter, log entries, idempotency, empty-input edge cases.
- `EmailRenderer`: synthetic inputs; topic-card ordering, Other Notable formatting, Errors section, light-signal branch, extra-channel resilience.
- `ErrorLog`: append behavior, summary grouping, severity counts, consequential-info promotion.
- `GmailSender`: unit test on MIME assembly (no network) + integration against the real Gmail API in draft mode (creates draft, asserts presence, deletes for cleanup). `mode="send"` not auto-tested.

Calls `init_run.py` to create a new run; copies `corpus.json` from the source run; writes `lineage.json` `{source_run_id, reused: ["corpus.json"], created_at}`; runs steps 5a (slow-day check), 6 (cluster), 7 (recommendations), 8 (email) of `run-trends`. New run is fully self-contained; the source run is untouched.
